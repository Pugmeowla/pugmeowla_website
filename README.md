# Pugmeowla's website

Static site: the project homepage (`index.html`) and the mod wikis (`wiki/`): **Infinity Stone Core** (`wiki/infinity/`) and
**Deus Chrono-Machina** (`wiki/deus-chrono-machina/`).
Everything is plain HTML/CSS/JS, so the whole folder can be pushed to GitHub and served with GitHub Pages.

```
index.html          homepage (project cards, links to the wiki)
404.html            not-found page (generated by the wiki build, used by GitHub Pages)
wiki/               the built wikis (generated, commit it, don't edit by hand)
  index.html        the list of wikis
  infinity/ …       the Infinity Stone Core 8.0 docs (7.3 in infinity/7.3/)
  deus-chrono-machina/  the Deus Chrono-Machina 7.0 docs
  assets/           CSS, JS, images and search indexes shared by every wiki and version
_wiki/              wiki sources
  build.mjs         the build: every wiki's and version's pages + data -> wiki/
  site.mjs          the wikis: name, links, output folder, their versions and which one is released
  <wiki>/<id>/      infinity/8.0, infinity/7.3, deus/7.0
    nav.mjs         that version's label, notice, output folder and sidebar / page order
    pages/          one HTML file per page, with a small front-matter header
    data/           stones, abilities, items, skins (index.mjs exports them)
  lib/              macros ({{item ...}} etc.), syntax highlighting, helpers
  static/           CSS, JS and images, copied to wiki/assets/
  tools/            asset sync (copies and renders images from the mod)
```

## Viewing it locally

Open `index.html` or `wiki/index.html` in a browser; it works straight from the disk. Or serve the folder:

```
python3 -m http.server 8000      # then open http://localhost:8000
```

## Building the wiki

Needs Node.js 18+ and nothing else (no npm install).

```
node _wiki/build.mjs
```

The build rewrites `wiki/` and `404.html`, generates the search index, and then checks every internal link, `#anchor`
and image. It exits with an error listing any problem, so a green build means no broken links.

## Editing content

- **A page**: edit `_wiki/<wiki>/<version>/pages/<page>.html`. The header sets `title`, `description`, `lead`, `icon` (path under
  `assets/img/`) and optionally `nav` (sidebar label) and `toc: h2`. Each page ends with links to the previous and next
  page in the nav order.
- **A new page**: add the file, then add its path to `nav` in that version's `nav.mjs` (the build refuses pages that
  aren't in the nav).
- **Links**: write `@/path.html` for pages in the same version, `@w/assets/img/...` for images and `@s/index.html` for
  the homepage. The build makes them relative.
- **Macros** inside pages:
  `{{item tesseract}}`, `{{stone space}}`, `{{ab space/teleport}}`, `{{page commands.html Commands}}`,
  `{{abilities power}}` (ability cards), `{{costtable soul}}`, `{{itemcards orb}}`, `{{figure src="gui/portal.png" caption="..."}}`.
  The full list is in `_wiki/lib/macros.mjs`.
- **Code blocks**: `<pre data-lang="json" data-title="file.json">...</pre>` (also `command` and `text`) get
  highlighting and a copy button.
- **Callouts**: `<div class="callout tip|warn|compat">`, **tabs**: `<div class="tabs" data-tabs><section data-tab="Name">`.
- **Other mods**: `data/mods.mjs` lists every other mod the pages mention, with its Modrinth and CurseForge links and
  icon (`static/img/compat/`). The build links each mention automatically; readers pick Modrinth or CurseForge in the top bar.
- **Abilities, items, skins**: edit the files in that version's `data/` folder. The ability list, item index, skin gallery, stone
  pages and search all read from them.
- **Versions**: only 8.0 is documented right now, but the wiki can hold several. To add one (say 8.1):
  1. Copy `_wiki/infinity/8.0` to `_wiki/infinity/8.1` and set `id` and `label` to `8.1` in its `nav.mjs`.
  2. Give the newest version `outDir: ''` (it builds into `wiki/infinity/`) and move the older one to its own folder, e.g.
     `outDir: '8.0'` (it builds into `wiki/infinity/8.0/`).
  3. Add it to that wiki's `versions` in `_wiki/site.mjs`, newest first, and set `released` to the version on CurseForge and Modrinth.
  With two or more versions, the label at the top of the sidebar becomes a version switcher, and the `notice` in `nav.mjs`
  links to the released version's docs.

## Updating images from the mod

```
node _wiki/tools/sync-assets.mjs /path/to/infinity
```

Copies icons, block and GUI textures from the mod, renders inventory-style icons from the mod's item models (Orb,
Tesseract, Cosmi-Rod…), renders each gauntlet skin's worn GeckoLib model (`tools/render-geo.mjs`) and the Infinity Stone icons (the stone texture tinted with each stone's color),
into `_wiki/static/img/`. Then run the build. On macOS it also regenerates the banner and favicon with `sips`.

```
node _wiki/tools/render-extras.mjs /path/to/infinity [--addonpacks <folder>] [--generator <unzipped jar>] [--omnitrix <folder>] [--vanilla <folder>]
```

Renders the pictures in `_wiki/static/img/models/`: the Infinity Gauntlet and the addon mods' gauntlets worn on the player
with their stones in (Infintrix, Infinity Protocol, Herbs of Wakanda), the Burnt Gauntlet, the Time Stone rings, Malekith and
the Infinity Generator's blocks. `--addonpacks` defaults to the mod's `forge/run/addonpacks`. `--omnitrix` is a folder with the
Alien Evolution, Into the Omniverse and Omnitrix Evolution jars unzipped into it, so the Infintrix gloves are drawn on their Omnitrix. `--vanilla`
is a folder with the `assets` of the 1.20.1 client jar and Forge's universal jar unzipped into it, for the Temple Beacon and
the molten metal buckets in `renders/`.

## Skill trees and recipes (Infinity)

```
node _wiki/tools/sync-positions.mjs /path/to/infinity
node _wiki/tools/sync-recipes.mjs /path/to/infinity
```

`sync-positions` copies every visible skill tree node (abilities and the dummy entries that shape the letters) from the mod.s power files into `infinity/8.0/data/trees.mjs`, which
`{{skilltree <stone> bg=<color or texture> unit=<px>}}` draws on each stone page (abilities without a spot are listed under it with
`{{abilities <stone> notree=1}}`). `sync-recipes` writes the crafting and furnace recipes to `infinity/8.0/data/recipes.mjs`, shown by
`{{recipebook}}` on the Items page and in each item's details. Rerun both after changing the mod, then build.

## Ingredient pictures

```
node _wiki/tools/sync-ingredients.mjs --vanilla <assets/minecraft/textures> --palladium <palladium-common jar>
```

Copies the textures of vanilla and Palladium items used in recipes (the Infinity recipes and every `{{recipe}}` on the pages) into
`static/img/ingredients/`. Ingredients without a picture show their name instead.

## Deus Chrono-Machina images

```
node _wiki/tools/render-deus.mjs <unzipped Deus Chrono-Machina jar> [--alienevo <unzipped Alien Evolution jar>]
```

Copies the item and ability icons and renders Clockwork's uniforms, the Upgrade fusion, the mobs and Maltruant's fragments into
`_wiki/static/img/deus/`. `--alienevo` adds the Alien Evolution crafting ingredients shown in the recipes (`{{recipe ...}}`).
The Deus wiki's green and gold colors are the `html[data-wiki="deus"]` rules at the end of `wiki.css`; `{{skilltree tree}}` draws the
interactive skill tree from the `pos` of each tree entry in `data/abilities.mjs`.

## Old links

Before the wikis moved into their own folders the Infinity wiki lived at `wiki/`. The 404 page sends old links like
`wiki/stones/power.html` on to `wiki/infinity/stones/power.html`.

## Publishing on GitHub Pages

1. Push this folder to a repository.
2. Settings → Pages → Deploy from a branch → the branch, folder `/ (root)`.

`.nojekyll` makes Pages serve the files as they are. All links are relative, so the site works both as a user site
(`username.github.io`) and a project site (`username.github.io/repo/`). The 404 page guesses the base path for project
sites from the URL.
