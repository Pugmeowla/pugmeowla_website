--- title: Gauntlet Skin Files nav: Skin Files description: The gauntlet_skins format: add an Infinity Gauntlet skin with one JSON file and its textures, including custom models, glow layers and replacement rules. lead: A skin is one JSON file plus its textures. The mod generates the apply ability, skill tree entry, item look and render layers for you. icon: skins/sith_gauntlet.png ---

What one file gives you

Apply ability (infinity:set_gauntlet_skin) and skill tree entry
Added to the infinity:infinity_gauntlet power where its {"infinity:generate": "gauntlet_skins"} placeholder sits.
Inventory item look
The gauntlet's item model, retextured with the skin's icon texture.
Worn, main hand and ground look
A generated Palladium (GeckoLib) render layer, picked by the infinity:gauntlet_skin_layer abilities.
/infinity gauntlet skin set|clear
Suggests the skin, and gives back its unlock item on clear. Only changes a gauntlet held in the main or off hand.
infinity:gauntlet_skin condition
Works with the skin ID.

The apply ability uses one unlock item (held in the main hand), sets the skin, plays the apply sound and runs apply_commands. It reaches a gauntlet held in either hand or worn in the Curios hands slot. It only appears while the gauntlet has no skin, or one listed in can_replace.

Worked example: a Gold Gauntlet

Skin files go in data/<namespace>/infinity/gauntlet_skins/, where <namespace> is your mod or pack ID. The skin ID is <namespace>:<file name> and its textures are looked up in your namespace, so two mods can't replace each other's skins. The older data/infinity/gauntlet_skins/ folder still works, with just the file name as the ID: that's where the mod's own skins live.

1. Definition. In the Test Stone pack, this is the skin infinity_test_stone:gold_gauntlet.

{
  "title": "Gold Gauntlet",
  "unlock_item": "minecraft:gold_ingot",
  "description": "Unlock by right-clicking with a Gold Ingot in your main hand."
}

2. Textures, named after the file, in assets/infinity_test_stone/textures/:

models/gold_gauntlet.png
The gauntlet worn, in the main hand and on the ground (same UV layout as models/gauntlet.png for geo/gauntlet.geo.json).
item/gauntlet_skins/gold_gauntlet.png
Inventory item and skill tree icon (same layout as item/infinity_gauntlet_item.png).

That's it. Restart the game. Missing textures or models fall back to the normal gauntlet's, with a warning in the log.

Instead of description you can add the lang key ability.infinity_test_stone.gauntlet.gold_gauntlet.description (ability.<namespace>.gauntlet.<file name>.description).

All fields

Only unlock_item is required.

unlock_item

Default
required
Meaning
Item held in the main hand to apply the skin. One is consumed, and given back when the skin is removed. Must be a registered item, or the skin is skipped.

title

Default
ID in title case
Meaning
Name in the skill tree and ability bar.

description

Default
lang key ability.infinity.gauntlet.<id>.description
Meaning
Text or text component shown in the skill tree.

apply_on

Default
right_click
Meaning
right_click, or hold to apply as soon as the item is held.

apply_sound

Default
minecraft:block.anvil.land
Meaning
Sound played on apply.

bar_color

Default
black
Meaning
Ability bar color (a Palladium ability color name).

hidden_in_bar

Default
false
Meaning
Hide the apply ability from the ability bar, for secret skins.

gui_position

Default
next free slot
Meaning
[x, y] in the gauntlet's skill tree. Without it: the first free slot in rows of five (x = −1 to 1, step 0.5) from y = 2.5.

can_replace

Default
[]
Meaning
Skin IDs this skin may be applied over. Normally the gauntlet must have no skin.

apply_commands

Default
[]
Meaning
Extra commands run as the player after applying.

icon

Default
<namespace>:item/gauntlet_skins/<file name>
Meaning
Skill tree icon and inventory item texture, as a sprite under textures/ (no textures/ or .png. A full texture path is accepted too).

render.texture

Default
<namespace>:textures/models/<file name>.png
Meaning
Model texture.

render.model

Default
infinity:geo/gauntlet
Meaning
GeckoLib model prefix, without .geo.json. _mainhand and _ground are appended for those positions, so a custom shape needs all three files.

render.glow

Default
off
Meaning
true adds an emissive layer using <texture>_glow.png. An object allows texture, enchantment_glint, conditions (Palladium conditions, e.g. night only) and positions (any of worn, mainhand, ground).

render.layers

Default
none
Meaning
{"worn": "infinity_test_stone:my_layer", …}: use your own Palladium render layer for that position instead of the generated one.

Examples from the mod

Minimal

{
  "title": "Netherite Gauntlet",
  "unlock_item": "minecraft:netherite_ingot",
  "gui_position": [0, 2.5]
}

Custom model + glint

{
  "title": "Dragon Gauntlet",
  "unlock_item": "minecraft:dragon_head",
  "bar_color": "purple",
  "gui_position": [0, 4],
  "render": {
    "model": "infinity:geo/dragon_gauntlet",
    "glow": { "enchantment_glint": true }
  }
}

Glow at night

{
  "title": "Midnight",
  "unlock_item": "minecraft:black_dye",
  "gui_position": [-1, 3.5],
  "render": {
    "glow": {
      "positions": ["worn"],
      "conditions": [ { "type": "palladium:night" } ]
    }
  }
}

Apply on hold

{
  "title": "Gauntlet with Fingers",
  "unlock_item": "minecraft:chicken",
  "apply_sound": "minecraft:entity.generic.eat",
  "apply_on": "hold",
  "gui_position": [1, 2.5],
  "render": {
    "model": "infinity:geo/finger_gauntlet",
    "texture": "infinity:textures/models/gauntlet.png"
  }
}

Replace + commands

{
  "title": "Nano Gauntlet Skin",
  "unlock_item": "palladium:vibranium_flux_capacitor",
  "apply_sound": "infinity:nano_gauntlet",
  "bar_color": "red",
  "gui_position": [-1, 2.5],
  "can_replace": ["gauntlet_burn"],
  "apply_commands": ["tag @s remove burn_texture"]
}

Extending the format (Java)

GauntletSkin keeps the raw JSON (skin.json), so new code can read a new key without changing the parser. Apply abilities are built in GauntletSkinAbilities and render layers in GauntletSkin.renderLayerJson.
