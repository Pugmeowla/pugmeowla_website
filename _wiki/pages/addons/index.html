Rules shared by all four systems

  • Files always go in the infinity namespace folder (data/infinity/…), in your addon pack or mod. The file name is the ID.
  • Files are read from every mod and every pack in the addonpacks folder. If two packs have a file with the same name, the higher-priority pack wins, so an addon can replace one of the mod's own files.
  • File names starting with _ are ignored (handy for templates and disabled files).
  • They're read once at startup. Restart the game after changing them; /reload isn't enough.
  • Parsing is lenient: an invalid value falls back to its default, an invalid file is skipped, and the problem is logged once (Gauntlet stone <id>: …, Gauntlet skin …, Custom gauntlet …, Ground item …). Check logs/latest.log if something doesn't show up.

Setting up an addon pack

Infinity Stone Core is a Palladium addon itself, and its content uses Palladium's addon pack format. The quickest way to extend it is your own addon pack: a folder (or zip) in .minecraft/addonpacks/, containing data, assets and Palladium's addon/ folder for new items and blocks. See Palladium's documentation for the pack format itself.

addonpacks/chaos_stone_pack/
├── pack.mcmeta
├── addon/example/items/chaos_stone.json                 the item (Palladium addon item)
├── assets/example/models/item/chaos_stone.json          {"parent": "infinity:item/infinity_stone"}
├── assets/example/lang/en_us.json
├── data/example/palladium/powers/chaos_stone.json       the stone's power and abilities
├── data/infinity/gauntlet_stones/chaos_stone.json       makes it fit in the gauntlet
└── data/infinity/ground_items/chaos_stone.json          optional: lies on the ground like a stone

The same files work inside a regular mod's src/main/resources.

Working with the mod's powers

  • The stone powers are infinity:space_stone, infinity:mind_stone, infinity:reality_stone, infinity:power_stone, infinity:time_stone and infinity:soul_stone; the gauntlet's is infinity:infinity_gauntlet. Use palladium:has_power to check for them.
  • To check what's in a gauntlet use infinity:gauntlet_slot; for "is this stone available at all" use infinity:stone_equipped. All conditions and ability types are on the {{page addons/abilities.html reference page}}.
  • To add the generated skin abilities to your own power, put an entry {"infinity:generate": "gauntlet_skins"} among its abilities, as the gauntlet power does: it's replaced with every skin's apply ability and skill tree entry at load time.
  • Scoreboard objectives the mod uses, which conditions and energy bars can read: DamageCycle (Power level), SoulStorage (souls), tickrateCycle and timestonesidebar (Time Stone step), power_stone … mind_stone (1 while that stone is in the worn gauntlet).

In-game reference

When Palladium generates its documentation (into mods/documentation/), the mod adds reference pages for its formats under infinity/: gauntlet_stones.html, gauntlet_skins.html, custom_gauntlets.html and ground_items.html, and documents its ability and condition types in Palladium's own pages. They're generated from the code, so they always match the version you have installed.

Real examples

  • Pugmeowla's Infintrix turns four Omnitrixes into power gauntlets with gloves (custom gauntlets).
  • Infinity Protocol makes the Iron Man MK85 suit an item gauntlet whose stones only show during its nano-gauntlet animation.
  • The mod's own data/infinity/gauntlet_skins, gauntlet_stones and ground_items folders are good templates.
