How these files are read

  • They go in data/<namespace>/infinity/<folder>/, where <namespace> is your mod or pack ID. The ID is <namespace>:<file name> (for example gem_core:ruby_gauntlet), so two addons can never replace each other's files by accident.
  • The older data/infinity/<folder>/ still works, with just the file name as the ID. The mod's own files live there, so a file with the same name there in a higher priority pack replaces one of the mod's own.
  • The mod reads them from every mod and every pack in the addonpacks folder.
  • File names starting with _ are skipped, which is handy for templates and switched off files.
  • They're only read when the game starts, so restart after changing them. /reload won't pick them up.
  • A bad value falls back to its default and a broken file is skipped. Either way it gets logged once (Gauntlet stone <id>: …, Gauntlet skin …, Custom gauntlet …, Ground item …), so check logs/latest.log if something doesn't show up.

Making an addon pack

Infinity Stone Core is a Palladium addon itself, and its content uses Palladium's addon pack format. The easiest way to add to it is your own addon pack: a folder (or zip) in .minecraft/addonpacks/ with data, assets and Palladium's addon/ folder for new items and blocks. The pack format itself is covered in Palladium's documentation, and the Palladium addon pack template generator makes an empty pack to start from.

The examples on these pages come from infinity_test_stone, a working test pack that adds a pink Test Stone. It was made before namespaced folders, so its stone and ground item files use the older data/infinity/ folder, which still works:

infinity_test_stone/
├── pack.mcmeta
├── addon/infinity_test_stone/items/test_stone.json                  the item (a Palladium addon item)
├── assets/infinity_test_stone/models/item/test_stone.json           {"parent": "infinity:item/infinity_stone"}
├── assets/infinity_test_stone/lang/en_us.json                       the item's name
├── assets/infinity_test_stone/ability_overlays/illusions.json       optional, themes one ability in the skill tree
├── data/infinity_test_stone/palladium/powers/test_stone.json        the stone's power and abilities
├── data/infinity/gauntlet_stones/test_stone.json                    makes it fit in the gauntlet
└── data/infinity/ground_items/test_stone.json                       optional, makes it lie on the ground like a stone

pack.mcmeta

{
  "pack": {
    "id": "infinity_test_stone",
    "version": "1.0.0",
    "description": "Test Gauntlet Stone addon for Pugmeowla's Infinity Stone Core",
    "pack_format": 15
  },
  "dependencies": {
    "common": {
      "infinity": ">=7.4"
    }
  }
}

Item

{
  "max_stack_size": 1,
  "rarity": "epic",
  "is_fire_resistant": true,
  "creative_mode_tab": {
    "tab": "infinity:infinity",
    "after": "infinity:mind_stone"
  }
}

Name

{
  "item.infinity_test_stone.test_stone": "Test Stone"
}

The same files work in a normal mod's src/main/resources.

Using the mod's powers

  • The stone powers are infinity:power_stone, infinity:space_stone, infinity:reality_stone, infinity:soul_stone, infinity:time_stone and infinity:mind_stone. The gauntlet's is infinity:infinity_gauntlet. Check for them with palladium:has_power.
  • To check what's in a gauntlet use infinity:gauntlet_slot. To check whether a stone is available at all use infinity:stone_equipped. Every condition and ability type is on the {{page addons/abilities.html reference page}}.
  • To give your own power the generated skin abilities, add an entry {"infinity:generate": "gauntlet_skins"} to its abilities, like the gauntlet power does. When it loads, that entry is swapped for every skin's apply ability and tree entry.
  • Scoreboard objectives you can read in conditions and energy bars: DamageCycle (power level), SoulStorage (souls), and tickrateCycle and timestonesidebar (Time Stone step). The old power_stone to mind_stone objectives for stones in the gauntlet are gone in 8.0: use infinity:gauntlet_slot instead.
  • To let players switch part of your power off, add an infinity:toggle ability and check its setting with the infinity:setting condition, like the stones' passive toggles.

In-game reference

When Palladium generates its documentation (into mods/documentation/), the mod adds its own pages under infinity/: gauntlet_stones.html, gauntlet_skins.html, custom_gauntlets.html, ground_items.html, stone_containers.html and ability_overlays.html. Its ability and condition types go into Palladium's own pages. They're generated from the code, so they always match the version you have.

Real examples

  • Pugmeowla's Infintrix turns four Omnitrixes into power gauntlets: the Prototype, Recalibrated and Ultimatrix with gloves, and the Omniverse Omnitrix with its stones around the watch face. Its own power uses infinity:gauntlet_slot: with the Power Stone in, the Omnitrix times you back in straight away, and with all six it unlocks every alien and Master Control, which a Snap burn takes away again.
  • Pugmeowla's Infinity Protocol makes the Iron Man MK85 suit from Satsu's Iron Man Addon a power gauntlet, worn only while the suit's nano gauntlet is out. With all six stones in, it also keeps refilling the suit's energy, nanites and Pym particles.
  • The mod's own data/infinity/gauntlet_skins, gauntlet_stones and ground_items folders are good to copy from.
